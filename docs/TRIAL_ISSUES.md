# Live Production Trial 问题记录

## TLI-006 · 后台对象入口分散、页面过长，负责人找不到单式返修操作

- 类别：UX / Workflow；优先级：P1（用户无法独立找到关键操作）。
- 角色与步骤：负责人从功法管理进入《流云掌》招式，查看讲解与跟练后，准备只修改讲解提示词并制作新版；同事需要从自己的生产任务进入相应教学包。
- 期望：按“功法列表 → 功法详情 → 招式详情”定位对象；列表按状态筛选和搜索；详情在固定页内切换内容分区；任务、素材、版本和审核各有明确位置，可直接返回上级。
- 实际：旧菜单同一对象有多处入口；功法、招式、任务、老师、AI 能力管理等详情纵向堆叠大量内容；素材中心同时展开所有筛选；浏览器返回不能可靠回到前一对象。用户需要口头说明修改提示词的位置。
- 处理：合并角色菜单；功法、生产任务、管理任务改为状态 Tab 列表并提供搜索；功法、教学包、老师、通用任务、项目、AI 管理页改为页内 Tab；招式保留七个可直达的工作分区和顶部单条视频优化入口；素材中心首屏保留常用分类与搜索，高级筛选按需展开；增加可返回上级的面包屑及浏览器历史。
- 线下沟通逃逸：用户在聊天中反复询问返修入口，属于操作解释离开 Work OS；未观察到正式文件通过外部聊天传递。
- 验证范围：本次结构调整经过静态检查和 HTTP 回归测试；还需现场让未参与开发的负责人、武术／运营、美术同事分别完成自己的路径，记录误点、回退和口头解释次数。此项不能仅凭代码发布宣布 UX 验收通过。

## TLI-001 · 《流云掌第二式》双真人视频无法进入 AI 准备

- 类别：Workflow / UX；优先级：P0（阻塞本式继续制作）
- 角色与步骤：武术／运营，上传真人视频 → 确认参考片段 → 分别保存讲解与跟练视频方案。
- 期望：讲解、跟练各自绑定已确认的真人参考；两项保存后可进入 AI 准备。
- 实际：界面及后端只认可最新的一条参考；上传第二条后，第一条的已保存方案被隐藏，AI 准备保持不可达。
- 判定：系统流程缺陷；真实双视频使用路径复现，无需新增自动化岗位。
- 处理：视频方案分别选择并保存真人参考 ID；界面并排显示两条参考和各自预览；AI 准备、候选、报价、返修与任务输入按轨道追溯。原单参考生产包保持有效。
- 线下沟通逃逸：本次由用户在聊天中报告，正式问题已回写本记录；未观察到文件通过微信或群聊传递。
- 验证范围：隔离环境覆盖“先保存讲解 → 上传并确认第二条 → 保存跟练 → AI 准备 → 分轨报价及作业参考”；线上《流云掌第二式》已看到讲解 V1（21.20 秒）、跟练 V2（7.97 秒）各自保存，AI 准备入口已解锁。仍待实际操作人验证入口与理解成本；未把测试或旧素材计为正式 Motion Approved。

## TLI-002 · 静态练功背景进入视频生成

- 类别：Workflow / Asset / AI Quality；优先级：P1（上传后易误以为生成任务已使用该图）。
- 角色与步骤：美术，交付每套功法的练功背景。
- 期望：每套功法上传各自的一张静态练功背景。视频生成以此图约束场景布局和风格，再用提示词使云、雾、光影等环境元素产生适度动态；数字老师动作仍以真人参考为准。同一功法各式复用该背景版本。
- 当前：功法管理支持静态练功背景直传、预览和功法级版本关联；已领取本功法背景任务的美术同事可从教学包进入上传。新建的常规讲解／跟练生成作业会锁定当时的背景资产 ID、版本和 SHA-256，将老师图与该背景图分别作为图片 1、图片 2 传入润元 Seedance，并在提示词中要求远景原有流云／薄雾轻缓浮动、练功场结构稳定。缺背景或文件校验失败时，新作业不能开始。已有视频作业不会被改写。各式教学包仍须关联实际采用的背景版本以满足正式资产门槛；视频编辑双图试拍仍属于独立试拍。
- 阻塞性：静态图上传与生成输入的代码路径已接通；模型能否在真实成片中同时保住背景布局、云雾自然运动和真人动作，需要用用户已上传的真实图及后续试生产视频实际验收。测试中的双图请求与提示词锁定不等于画面已通过验收。
- 处理：新作业提交前在报价处显示背景名称与版本；真实生成后由美术核对场景和云雾、武术岗位核对动作，并记录偏差与必要返修。此项不要求上传动效视频，也不自动发起付费试拍。

## TLI-003 · 5 秒预估价误作每招默认预算，AI 准备与背景提示词关系不清

- 类别：Workflow / UX / Bug；优先级：P1（正式制作可能被错误预算上限拦截）。
- 角色与步骤：运营制作，查看讲解和跟练费用、上传练功背景后准备生成。
- 期望：背景换版后直接在新视频中使用，并自动带上轻缓动态要求；费用估算供提交前核对，不由系统擅自给每招设 3.6 元上限。
- 实际：5 秒 Seedance 2.5 预留估值 3.6 元曾被复用为新任务预算上限；界面突出显示预算设置。AI 准备生成的两条教学建议不包含当前背景，新视频实际提交提示词会另外拼入背景规则，容易误以为要重新付费生成 AI 准备。
- 处理：新招默认不设任务预算上限；升级时仅迁移未被负责人手动设过预算的系统自动任务，显式上限继续有效。界面保留费用估算，单招上限收进可选设置。AI 准备处说明背景上传或换版无需重新准备，制作新视频时自动引用当前背景版本和动态画面要求。
- 验证范围：隔离数据库覆盖新任务默认、旧默认迁移、负责人显式上限保留；静态检查确认正式视频的背景图与动态文字进入提交链路。真实成片里的云雾效果仍待现场审看。

## TLI-004 · 单条讲解或跟练视频无法按提示词／真人素材独立优化

- 类别：Workflow / UX / AI Quality；优先级：P1（真实返工入口不清，容易误改另一条视频）。
- 角色与步骤：运营制作，查看讲解成片后发现动作偏离真人、地板变为山峰且画面变暗，想修改提示词并只重做讲解。
- 期望：可从讲解卡片进入，编辑本次实际发给 Seedance 的修正提示词，核对费用后生成新版；或仅换讲解真人视频。跟练及旧正式成片在新版通过动作验收前保持可用。
- 实际：AI 准备展示的是教学建议，不是最终提交提示词；已定版讲解的视频制作按钮被界面禁用。上传另一条真人视频后，旧逻辑还会把未改动轨道的候选与成片误判为过期。
- 处理：每条视频增加独立的“改提示词并生成新版”和“更换真人视频素材”入口。修正文字实际附加到本次 Seedance 请求，随作业记录保存并可查看；基础提示词强化地板、亮度和动作参考约束。已验收任务在明确发起完整视频新版时恢复制作状态。只在对应轨道的动作方案变化时使该轨道旧结果过期；新版通过验收并定版时才替换旧正式视频。
- 验证范围：隔离环境覆盖人工修正提示词进入实际作业、背景与动作参考锁定、单轨真人视频换版后另一轨正式视频继续有效；真实画面中的动作逐帧一致性、地板和亮度仍须由同事看片验收。

## TLI-005 · 单条视频优化入口不可见，重新生成绕过提示词编辑

- 分类／等级：UX、Workflow、Bug；P1；阻塞用户独立发起正确的返修任务。
- 角色与步骤：负责人在招式页查看讲解成片后，想沿用真人视频，先修改动作、地板和亮度要求，再单独生成讲解新版。
- 期望：招式页直接看到统一操作区，明确选讲解或跟练、当前真人素材与背景、提示词修改、费用和提交；需要时才换真人视频。负责人也能发起正式新版任务，原岗位负责人不变。
- 实际：提示词编辑藏在第 5 步，返修入口仍写“重新生成”；前两次部署没有更新 `index.html` 中的 `martial.js` 查询版本，而脚本缓存配置为 24 小时 immutable，用户可能一直加载旧界面。
- 处理：将完整视频新建／返修入口集中在招式页顶部；旧卡片和动作 QC 的入口都跳转到同一操作区；提示词草稿在页面自动刷新时保留；管理者可创建完整视频任务而不改变岗位归属；更新前端版本并使 martial 静态文件不再使用 immutable 缓存。
- 待现场验证：负责人刷新页面后，能否不经口头解释，沿用原真人素材、只改讲解提示词并创建新版任务；新版真实画面仍需武术人员验收。
